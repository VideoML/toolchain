The Linux container used `--network none`, a read-only root, a single task-owned project mount, 1.5 GiB memory, 256 PIDs and the preinstalled `/usr/lib/chromium/chromium-headless-shell`. This is portability evidence, not production sandbox acceptance. No browser download or lifecycle scripts ran. macOS used the existing Chromium 1243 headless shell and `/usr/local/bin/ffmpeg`; Linux used `/usr/bin/ffmpeg` 5.1.9.

The XML fixture declares and uses Geist via `videoml/particle-text-dissolve` `fontAsset: "font"`, with dry-run frozen audio. The trusted TS fixture imports the public DSL and GSAP and uses a custom async canvas component with a domain-warp transition. Each was locked with the Linux descriptor and exported once on macOS using the workflow in `docs/portable-bundles.md`, then the same ZIP was validated, imported, and rendered on each host. Imported source, script, timing, WAV and font byte hashes matched between hosts. RGBA comparisons at frames 0, 10 and 15 show the XML outputs differ at 0, 926 and 771 of 76,800 pixels respectively (maximum channel deltas 0, 197 and 194); TS frames 0, 10 and 15 match in this run. This does not establish pixel equivalence across platforms. P28 retains the pinned-environment release gate.

A Linux FFmpeg 5.1.9 regression was reproduced: `-frames:v` ended audio after three AAC frames. Duration limiting produced the correct 19 AAC frames. A separate encode-only probe with extra frames, start number 5, 30000/1001 fps and 440 Hz tone yielded exactly 10 video frames and 0.334 s of non-silent audio (decoded RMS 2859.4); zero duration produced no streams.
